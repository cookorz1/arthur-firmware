# 使用与排查

[返回项目首页](../README.md) · [版本记录](VERSIONING.md)

## 首次使用

1. 电脑通过网线接入 LAN，打开 **http://192.168.10.1**。
2. 主机名为 `jdy-cookorz`，用户名为 `root`，初始管理密码为 `password`。
3. 打开“网络 → 无线”，查看无线网络及初始密码，再按需要修改名称和密码。
4. 打开“网络 → 亚瑟网络面板”，查看 WAN/LAN/USB 网卡及 USB 总线速率，并设置 USB 上网开关。
5. 随身 WiFi 以 USB 共享网络模式连接后，默认尝试建立 DHCP 接口；如关闭 USB 上网，请在网络面板重新开启并“保存并应用”。为兼容旧版，内部接口名仍保留 `f50`。
6. 在 iStore 中按需安装应用；OpenClash 需导入自己的订阅或配置后开启。

### Wi-Fi 默认设置

| 项目 | 默认值 |
| --- | --- |
| 主机名 | `jdy-cookorz` |
| 管理账号 / 密码 | `root` / `password` |
| 2.4 GHz 名称 / 密码 | `jdy-cookorz2.4G` / `jdy-cookorz2.4G` |
| 5 GHz 名称 / 密码 | `jdy-cookorz5G` / `jdy-cookorz5G` |
| 加密 | WPA2-PSK / AES，可在界面中自行改为 WPA2/WPA3 |
| 2.4 GHz 信道 / 带宽 | 1 / HE20 |
| 5 GHz 信道 / 带宽 | 36（非 DFS）/ HE80 |
| 有线管理地址 | `192.168.10.1` |
| 时区 | 中国上海 |

这些默认值按设备所有者要求设置，适用于全新安装或恢复出厂配置。保留设置升级会继续使用原来的主机名、密码和无线配置。无线初始化等待两个频段配置都出现，最长重试约 60 秒；仅配置未自定义的默认 AP，不覆盖已有自定义网络。首次登录后可自行修改密码、国家及信道。管理密码在构建时生成 SHA-512 哈希，并保留上游其他系统账号。

### USB 速率说明

- **USB 行的链路速率**：读取 USB 网卡的 sysfs / ethtool 驱动报告，驱动未提供时显示“无法读取”。
- **USB 总线连接速率**：读取当前 USB 设备实际枚举速率，例如 `5000 Mbps`（USB 3.x）或 `480 Mbps`（USB 2.0），不以设备标称值代替。
- USB 上网关闭时，仍显示已插入随身 WiFi 的物理连接及总线速率。总线速率不代表 5G 蜂窝速率或互联网测速。

### 网络质量检测与信号强度的区别

打开“网络 → 亚瑟网络面板 → 网络质量检测”，点击“开始检测”。检测是手动触发的短时 IPv4 采样，不持续发送测试流量。

| 检测项 | 说明 |
| --- | --- |
| 上网来源 / IP | 分别查看宽带 WAN 和 USB 随身 WiFi 的接口状态与 IPv4 地址，支持 PPPoE 的实际三层接口 |
| 延迟 / 丢包 | 绑定对应接口，分别向 `223.5.5.5`、`119.29.29.29` 各发送 3 次 ICMP 请求；显示平均延迟和丢包率 |
| HTTPS 可达性 | 绑定对应接口，访问百度、腾讯 HTTPS 首页的响应头，保留证书校验；单个请求最多 4 秒，两来源并行检测 |
| 结果解释 | ICMP 被限制时，HTTPS 成功仍显示外网可达；HTTPS 失败而 ICMP 成功时分别显示，不直接判定断网 |
| 蜂窝 / 光信号 | USB/网线通常不传递 RSRP、RSRQ、SINR、RSSI 或光猫光功率；需要随身 WiFi/光猫开放专用接口，当前显示检测范围说明 |

本功能只检查预设接口 `wan` 和兼容接口 `f50`，使用当前系统路由、DNS 与透明代理策略，不修改路由或防火墙。IPv6-only 接入显示未取得 IPv4，不能据此判断 IPv6 断网。少量采样、测点阻断、DNS 或系统时间异常都可能影响结果；它不是测速或信号强度测量。

### 无线排障

如果干净刷入本版后仍搜不到无线，先等待约一分钟，再通过有线登录终端查看以下输出。配置及信道调整不能代替实际射频测试。

```sh
ubus call network.wireless status
iw dev
logread | grep -Ei 'ath11k|hostapd|wireless|arthur' | tail -n 100
```

### USB 开关的范围

- **开启：** 发现 USB 共享网卡后建立或启用 `f50` DHCP 接口，加入 WAN 防火墙区；已配置的共享设备仍在时优先保留它，第二台设备插入不会抢占。
- **关闭：** 关闭 `f50` 网络接口并禁止其自动启动；随身 WiFi 仍然供电，USB 设备本身不会被断电。
- **重新插拔 / 重启：** 使用已保存的开关状态。
- **其他网络：** 保留有线 WAN 与 LAN 设置；有线 WAN 的路由优先级仍按当前接口配置决定。

## 加速与内存管理

入口：**网络 → 加速与内存**。保留亚瑟的 IPQ6018 / NSS 11.4 和 ath11k 512 MiB 内存配置，不超频，不放大 TCP 缓冲区或连接跟踪上限。

| 功能 | 默认值与实际范围 |
| --- | --- |
| TCP 拥塞控制 | BBR；可切回 Cubic。影响路由器自身与代理出口的内核 TCP 新连接，不改变手机/电脑的 TCP 算法，不为 UDP/QUIC 加速 |
| 默认队列 | FQ；只设置新队列默认值，不替换已有 mq、CAKE、HTB 或其他 SQM 树 |
| 转发加速模式 | 软件流量分载（rc.5 全新安装默认）、NSS 自动兼容、关闭；保留配置升级沿用原选择。软件模式先清退并卸载 ECM，NSS 模式先撤销软件规则，两者互斥 |
| 软件流量分载 | USB 上网可手动选择对比；对符合 fw4 规则的转发连接生效，不限于 USB。硬件流量分载保持关闭，不强开 GRO-list；页面显示实际规则是否存在，不把规则存在当作连接命中 |
| OpenClash 保护 | 配置已启用或核心仍运行时，暂停 NSS 与软件转发加速并清退规则，保留连接跟踪表；无法完成保护时阻止启动或重载代理 |
| USB 多核分流（RPS） | rc.5 默认开启，自动识别随身 WiFi 接口，四核亚瑟设置在线 CPU0/1/3（掩码 b），重启或重连后恢复；OpenClash 与 SQM 保护期间保留，不绕过代理或整形 |
| 代理关闭后 | OpenClash 配置关闭且进程退出、SQM/QoS 未启用时恢复所选模式。NSS 模式另外要求软件包分载未开启，不提供绕过兼容保护的强制开关 |
| 无线 NSS | 保留原生驱动，独立显示状态；NSS 无法代替代理加解密。USB 流量是否支持 NSS 由驱动和连接类型决定，页面连接计数是全机统计 |
| 冲突管理 | 硬件流量卸载始终关闭，软件模式不加载 ECM。SQM/QoS 工作时暂停两种转发加速，保留整形效果；软件包分载开启时暂停 NSS |
| ZRAM | 全新安装默认 128 MiB、lzo-rle 压缩交换，按需占用 RAM；保留已有自定义大小。开启/关闭下次重启生效，不在低内存时强制 swapoff |
| 手动释放缓存 | 同步数据后回收干净缓存与可回收 Slab，展示实际前后可用量；60 秒间隔，不结束进程、不删除临时目录，不清空交换或连接 |

OpenClash 启动和重载前有同步保护钩子，停止过程中仍保持保护。控制失败时阻止继续启动代理并显示日志，避免静默绕过规则；后台每 5 秒检查配置和进程状态。保护对 NSS 和软件模式均生效，不承诺代理开启时仍能使用转发分载。软件模式保持后台保护运行，不必执行之前排查用的手动停止服务命令。

选择“软件流量分载”后点“保存并应用”。正常状态显示“软件流量分载规则已启用；ECM 已退出”；打开 OpenClash 后应显示兼容保护，关闭 OpenClash 且核心退出后恢复软件模式。若 ECM 无法退出、模块缺失或防火墙应用失败，页面会显示错误，取消启用并尝试恢复普通转发；不要手动强开另一个加速器。切换会重载防火墙规则，建议在有线管理连接下操作。ZRAM 与内存清理设置不受模式切换影响。

### USB 多核分流与 OpenClash

rc.5 的“开启 USB 多核分流（RPS）”默认勾选；升级已有配置时，只补充缺失选项，保留明确关闭的选择。无需再手动向 `rps_cpus` 写入 `b`。开机或热插拔后自动检查，后台每 5 秒复核。已配置的 USB 共享设备优先，不接管板载网卡、无线、普通 USB 以太网适配器或原始 QMI/MBIM 接口。

OpenClash 开启后，页面可同时显示“OpenClash 兼容保护中”和“USB 多核分流已启用 · OpenClash 运行时保留”。前者暂停可能绕过代理处理的 NSS/软件流量分载；后者只分散接收处理。它们是两个独立层次，RPS 不保证代理仍能达到关闭代理时的测速。

关闭此选项并保存应用，会恢复接管前的 RPS 掩码；不会重启无线、改动 USB 中断亲和性或清空连接跟踪。运行 NSS 转发时暂不叠加，OpenClash 暂停 NSS 后可恢复；接口全局软件包分载已开启时交由 netifd 管理，避免两套配置相互覆盖。

`ubus call arthur performance` 中的 `usb_rps` 显示开关、实际设备、目标掩码和各接收队列的当前掩码。只有读取到所有接收队列符合目标才显示 `active`；等待设备、全局接管、NSS 运行和应用错误分别说明。可结合 [Linux RPS 文档](https://docs.kernel.org/networking/scaling.html) 理解其范围。

NSS 上游原启动/停止脚本会写入连接跟踪清空节点，本固件使用独立控制入口替代。改变性能设置不会为已连接的 USB 上网接口重复执行 ifup。BBR 不承诺提高运营商带宽；NSS 连接数、实际算法和内存值均从内核读取，无法读取时显示未就绪或未知。

Linux 会自动回收缓存，内存占用高不等于内存耗尽，应关注 **MemAvailable**。手动缓存回收不能释放 OpenClash 规则或程序堆内存，频繁回收会增加 CPU/I/O；没有设置定时清理。ZRAM 是压缩内存，不是额外物理内存，也不保证大规则集永不触发 OOM。

所有 feeds 固定到前一成功构建的提交（`feeds.lock.json`），主源码与插件提交仍见 `versions.env`。每次构建产生独立 LuCI 页面 URL 和 `/etc/arthur-build`，页面显示构建标识。

参考：[Linux TCP 设置](https://docs.kernel.org/networking/ip-sysctl.html)、[缓存回收说明](https://docs.kernel.org/admin-guide/sysctl/vm.html#drop-caches)、[ZRAM 文档](https://docs.kernel.org/admin-guide/blockdev/zram.html)。


## F50 直连更快，经亚瑟只有约 300 Mbps

我会先对照测速路径，再决定调整哪一层。请固定 F50 的位置、同一测速设备和测速节点，尽量在相近时间连续比较；蜂窝网络本身也会波动。

| 对照结果 | 优先检查 |
| --- | --- |
| 亚瑟网线测速能到 400–500 Mbps，5 GHz Wi-Fi 只有约 300 Mbps | 无线信号、终端协商速率、实际带宽是否为 80 MHz、信道干扰及终端能力 |
| 亚瑟网线和 Wi-Fi 都约 300 Mbps | USB 枚举速度、F50 的 USB 共享模式、路由负载和实际加速状态 |
| F50 USB 直连电脑也慢，但连接 F50 自己的 Wi-Fi 更快 | F50 的 USB 共享链路、数据线、USB 模式及驱动；两种接入路径要分别测 |

“网络 → 亚瑟网络面板”中 **USB 总线速率**若为 `480 Mbps`，表示 USB 2.0 High-Speed；`5000 Mbps` 表示 USB 3.0 SuperSpeed。两者是总线速度，不能当作互联网实测速率。也可在 SSH 中执行 `lsusb -t` 查看。

OpenClash 完全关闭后，还应在“加速与内存”看 NSS 的实际状态；SQM / QoS、手动关闭 NSS 等设置也会影响加速。USB 这条连接是否实际被 NSS 接管要结合运行计数确认，不能只看“已加载”。测速时可用 `top` 后按 `1` 查看每核负载（以当前 top 支持的显示方式为准）；总占用不高也可能存在单核处理瓶颈。

rc.4 新增软件流量分载选项。此次实机排查中，设备所有者反馈独立软件分载突破 400 Mbps，原设置开启 OpenClash 后约 350 Mbps；这是手动对照结果，不是新镜像的完整验收，也不保证固定吞吐。OpenClash 开启只说明核心在运行，测速连接可能按规则直连，不能据此把该数值当作代理节点速度。

BBR 作用于路由器本机 TCP 连接，无法解决 USB 2.0 或无线链路的带宽瓶颈；强行绕过 OpenClash / NSS 兼容保护也不能替代排查。软件分载有效后仍有差距，需要继续对照内核、USB 处理与实际网络条件。

参考：[Linux USB 速度定义](https://docs.kernel.org/driver-api/usb/usb.html)、[OpenWrt 无线带宽设置](https://openwrt.org/docs/guide-user/network/wifi/basic)、[Linux 网络多核处理](https://docs.kernel.org/networking/scaling.html)。
